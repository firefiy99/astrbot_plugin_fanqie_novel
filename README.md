# 番茄小说下载助手

在 QQ 群里丢一条番茄小说分享链接，机器人自动把**整本书**抓下来、打包成 TXT，直接把文件发回来。

不用注册账号，不用登录番茄，不用配置 Cookie。

创作者：小星萤

## 它长什么样

> 下面是一次**真实运行**的记录。书名、链接、文件大小都是实测数据，仅作演示。
> 你自己用时，发的是你想下的那本书。

**你在群里发：**

```
https://changdunovel.com/t/4geS0m5pPy0/
```

**机器人回复：**

```
已收到，开始处理。
整本抓取完成后会自动把 TXT 发到这里。
```

**过一会儿（这本书实测约 40 秒）：**

```
《我真没想恋爱，可她们非要》完成，正在发送…
```

然后你就收到一个 `我真没想恋爱，可她们非要.txt` 文件。

这本书的实际数据：**4.6MB，138295 行，506 章**。

## 安装（3 分钟）

### 前提

你已经有能正常收发消息的 AstrBot + NapCat（或其它 OneBot 实现）。
如果机器人本身就还没跑起来，请先解决那个，本插件不负责这部分。

### 方式一：从 GitHub 直接装（推荐）

在 AstrBot 的 WebUI 里操作：

1. 打开 WebUI → 左侧 **插件市场**（或「插件」页）
2. 点 **从链接安装**，填入：

```
https://github.com/firefiy99/astrbot_plugin_fanqie_novel
```

3. 等它下载完，**重启 AstrBot**
4. 去 **配置** 页找到「番茄小说下载助手」，什么都不用改，保存即可

### 方式二：手动放文件夹

```bash
cd AstrBot/data/plugins
git clone https://github.com/firefiy99/astrbot_plugin_fanqie_novel.git
```

然后重启 AstrBot。

### 方式三：Docker 部署的 AstrBot

如果你用 Docker（插件目录挂载到宿主机）：

```bash
# 宿主机上操作
cd /你的挂载目录/astrbot/data/plugins
git clone https://github.com/firefiy99/astrbot_plugin_fanqie_novel.git

docker restart astrbot
```

如果你在国内拉不动 GitHub，用镜像：

```bash
git clone https://ghfast.top/https://github.com/firefiy99/astrbot_plugin_fanqie_novel.git
```

### 装完之后该看到什么

重启后查看 AstrBot 日志，应该出现：

```
[astrbot_plugin_fanqie_novel] 已加载，模式=auto
[fanqie] 获取后端 (1/3)            ← 首次会下载约 10MB 的后端程序
[fanqie] 后端就绪 10545760 字节
[fanqie] 启动后端 127.0.0.1:18423
[astrbot_plugin_fanqie_novel] 后端就绪 http://127.0.0.1:18423
```

**看到最后一行 `后端就绪` 就说明装好了。**

首次启动会下载后端程序，根据网速可能等 10 秒到几分钟。
这期间发链接会提示「后端准备中」，等一会儿再发就行。

## 怎么用

### 方式一：直接发链接（最简单）

把番茄小说的分享链接直接发到群里。

默认会先问你一句确认：

```
识别到番茄链接：7490373272979115070
确认下载请发送: /番茄 7490373272979115070
```

你照着发那条 `/番茄 数字` 就开始下载了。

> 嫌麻烦？把配置里的 **「群里直接贴链接即开始下载」** 打开，
> 以后发链接就直接开跑，不再问确认。

### 方式二：用指令

```
/番茄 搜索 <关键词>   搜索书籍（一次返回 20 条）
/番茄 下载 <序号>     下载搜索结果里的第 N 本
/番茄 下一页          看下一页（/番茄 第N页 可直接跳页）
/番茄 <链接或书号>    下载这本书
/番茄 状态            看现在在下载什么
/番茄 取消            取消排队中的任务
/番茄 健康            检查内部下载器是否正常
/番茄 回链            自检文件回链是否可用
/番茄 清理            清理下载缓存（TXT 与记录）
```

### 支持哪些链接

| 你复制到的链接长这样 | 支持 |
| --- | --- |
| `https://changdunovel.com/t/XXXXXXXX/` | ✅ 最常见，番茄App点分享得到 |
| `https://fanqienovel.com/page/7490373272979115070` | ✅ |
| `https://changdunovel.com/ug/pages/book-share?...book_id=xxx` | ✅ |
| 直接一串数字 `7490373272979115070` | ✅ |
| 普通网址或纯文字 | ❌ 会提示没识别到 |

### 搜索书籍

不知道书号也能下。先搜：

```
/番茄 搜索 凡人修仙
```

（会先回一句「正在搜索…」，上游单次约需 3~5 秒）

返回示例：

```
搜索「凡人修仙」共 20 本（显示前 10 本）

1. 凡人修仙，从药童入道，执掌天道
   嘴里的手指 · 传统玄幻 · 205.1万字 · 完结
2. 凡人修仙，开局看守废丹房
   枫舟问禅 · 东方仙侠 · 907.2万字 · 连载
...

下载请发送：/番茄 下载 <序号>，例如 /番茄 下载 1
```

然后发：

```
/番茄 下载 2
```

就会开始下载第 2 本。

**翻页**

搜索结果超过一页时（后端单次最多返回 20 条，默认每页 10 条），会显示「第 1/2 页」。
翻页有三种方式：

```
/番茄 下一页      往后翻
/番茄 上一页      往前翻
/番茄 第2页       直接跳页
```

> **序号是全局的**：第 2 页显示的是 11~20，下载时直接用这个序号，
> 不用换算成页内序号。

**注意几点：**

- **序号只在当前会话有效**，默认 10 分钟过期，过期要重新搜
- **序号和 book_id 不冲突**：`/番茄 1234567` 仍按 book_id 处理，
  只有带 `下载` 前缀才按搜索序号解析
- 后端一次最多返回 20 条，**没有分页**。搜不到就换个更精确的关键词
- 同一会话 5 秒内只能搜一次，防止把上游刷到限流

### 一次能下几本？

默认最多排队 3 本。为什么限制？因为番茄有反爬，**同时抓多本会一起失败**。
所以插件故意串行：一本下完再下一本。

### 缓存与清理

插件会用缓存避免重复下载。理解下面几点能省不少流量和时间。

**同一本书 24 小时内再发一次**，插件不会重新抓，直接把上次的 TXT 再发给你：

```
命中缓存（12 分钟前下载过），已重新发送。
```

缓存时长由配置里的「结果缓存时长」控制，默认 24 小时。

#### 什么时候该清理

| 场景 | 建议 |
| --- | --- |
| 硬盘空间不够了 | `/番茄 清理` |
| 想强制重新抓某本书（比如作者更新了章节） | `/番茄 清理` 后再发链接 |
| 改了文件名想重新生成 | `/番茄 清理` |
| 就是日常用 | 不用清，插件会自动管理 |

#### 指令

```
/番茄 清理            清理全部（TXT 文件 + 记录）
/番茄 清理文件         只删 downloads 里的 TXT，保留缓存记录
/番茄 清理内存         只清内存记录，不删文件
```

执行后会回：

```
已清理：文件 3 个（13.2MB），内存记录 3 条，后端缓存 2 项
```

#### 清理会删什么、不会删什么

**会删：**

- `downloads/` 下的 TXT 文件（就是发给你的那些）
- 内存里的下载记录（下次同一本书会重新抓）
- `library/` 下的后端缓存（每本约 20MB 的章节缓存，占地方的主要是它）

**不会删：**

- 后端程序本身（`bin/tomato`）
- 你的配置
- 正在下载中的任务

#### 硬盘占用参考

| 内容 | 大小 |
| --- | --- |
| 后端程序 | 约 10MB |
| 每本书的 TXT | 约 4~6MB |
| 每本书的后端缓存 | 约 20MB |

所以下 10 本书大约占 250MB，下多了记得清一下。

## 配置说明

在 AstrBot WebUI → 插件 → 番茄小说下载助手 → 配置，能看到这些项。

> **大部分情况你什么都不用改。** 下面标「常用」的才值得看。

### 常用

| 配置项 | 默认值 | 什么情况下要改 |
| --- | --- | --- |
| **群里直接贴链接即开始下载** | 关 | 嫌每次要确认麻烦，就打开 |
| **单文件发送上限（MB）** | 80 | QQ 发不出去大文件时，调小 |
| **结果缓存时长（小时）** | 24 | 同一本书经常重复下载，可调大 |
| **仅管理员可用** | 关 | 公共群怕被人乱刷，打开并在白名单填 QQ 号 |

### 不常用（默认值一般都对）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 后端模式 | `auto` | `auto`=插件自己管下载器；`external`=连你自己装的后端 |
| 外部后端地址 | `http://127.0.0.1:18423` | 只有选 `external` 才用得上 |
| 外部后端密码 | 空 | 同上 |
| 单本下载超时（分钟） | 40 | 超长连载书可以调大 |
| 进度轮询间隔（秒） | 20 | 调小进度更新快，但容易被番茄限流 |
| 队列上限（本） | 3 | 防刷用 |
| 关键节点进度播报 | 开 | 下载较久时会在 25%/50%/75% 报一次进度 |
| 管理员 QQ 白名单 | 空 | 逗号或换行分隔 |
| 文件回链地址 | 空 | **收不到文件时才需要填**，见「端口与网络」 |
| 兜底文件服务端口 | 18999 | 仅令牌服务不可用时才用，正常不用管 |

### 别搞混：三个「地址」各管什么

配置里有个「外部后端地址」，很容易和「文件回链地址」看串。它们的方向完全不同：

```
QQ 群
  ↓
AstrBot 插件  ──①「外部后端地址」──→  下载器（Rust，负责真去番茄抓书）
  │
  └──②「文件回链地址」──→  NapCat（负责把 TXT 上传给 QQ）
```

| 配置项 | 指向谁 | 什么时候生效 | 一般要不要改 |
| --- | --- | --- | --- |
| **后端模式** | — | 决定下面①是否启用 | ❌ 保持 `auto` |
| **外部后端地址** | ① **下载器** | 仅「后端模式」= `external` 时 | ❌ `auto` 模式下无效，不用管 |
| **文件回链地址** | ② **NapCat 取文件的入口** | 每次发文件时 | ⚠️ 先留空；收不到文件才填 |

**绝大多数人只用 `auto` 模式**：插件自己下载、自己启动并看护下载器（端口从 18423 起自动找空的），
所以「外部后端地址」「外部后端密码」这两项**填什么都不影响**。

只有当你自己另外跑了一个下载器、想让插件复用它，才需要把「后端模式」改成 `external`，
再把「外部后端地址」填成那个下载器监听的地址（如 `http://127.0.0.1:18423`）。

### 升级后看不到新配置项？

v1.3.0 新增了「文件回链地址」这一项。如果你升级后打开配置页**没看到它**，先确认插件版本：

```
插件列表里应显示 1.3.0
```

版本对但界面仍旧，是浏览器缓存了旧配置页，按 `Ctrl+Shift+R` 强制刷新（手机浏览器清一下站点缓存），
或退出登录再进一次。

> 即使界面上暂时没显示，该项在配置文件里已经生效（留空＝自动探测），不影响使用。

## 端口与网络

**先说结论：正常情况下你一个端口都不用配，也不用做任何端口映射。**

这是旧版最容易卡住人的地方，v1.3.0 已经彻底改掉了。

### 为什么以前会「显示完成但收不到文件」

旧版发文件时，插件会在自己容器里**另开一个监听端口**（18999，占用就往后找 28900…），
然后把 `http://容器IP:该端口/f/书名.txt` 交给 NapCat 下载。

问题在于：**这个端口只存在于 AstrBot 容器的内部网络里。**

```
宿主机/公网        ❌ 没人把 18999 映射出来
   │
   ├── AstrBot 容器   ← 18999 只在这里监听
   │        ↑
   └── NapCat 容器    ← 若不在同一网络，连过去就超时
```

一旦 NapCat 与 AstrBot 不在同一 Docker 网络（或 NapCat 在另一台机器），
NapCat 取不到文件，QQ 侧表现为**一直收不到**，而插件日志只写「正在发送…」。

这一点责任在作者：原设计假设「两容器一定互通」，实际部署里这个假设经常不成立。

### v1.3.0 的做法：复用面板端口，不自开端口

现在改用 **AstrBot 内置的文件令牌服务**：

```
http://<AstrBot地址>:6185/api/file/<一次性令牌>
```

即走面板（WebUI）那个端口。

| | 旧版 | v1.3.0 |
| --- | --- | --- |
| 监听端口 | 自开 18999/28900… | 不新开，复用 6185 |
| 需要端口映射 | 需要（文档没说清） | **不需要** |
| 需要改防火墙 | 可能 | 不需要 |
| 文件权限 | 暴露 downloads 全目录 | 一次性令牌，用完即失效 |

只要面板端口（6185）能从 NapCat 那边访问，文件就能发出来。

### 一键自检：`/番茄 回链`

在群里发：

```
/番茄 回链
```

返回示例：

```
文件回链诊断（面板端口 6185）
可用   http://172.22.0.1:6185
不可用 http://172.22.0.2:6185
结论：令牌回链可用，不需要任何端口映射
```

- 有任一「可用」→ 网络没问题，收不到文件就是 QQ 侧的事
- 全部「不可用」→ 按下一步手填地址

### 如果自动探测不准：手填地址

```
配置 → 文件回链地址 → http://172.22.0.2:6185
```

| 你的部署 | 填什么 |
| --- | --- |
| NapCat 与 AstrBot 同一 Docker 网络 | AstrBot 容器 IP，如 `http://172.22.0.2:6185` |
| NapCat 在宿主机 | `http://172.17.0.1:6185` 或宿主机内网 IP |
| 跨机器 | AstrBot 所在机器的内网 IP |
| 有反向代理 + 域名 | 直接填域名 |

查容器 IP：

```bash
docker inspect astrbot --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
```

**注意**：面板端口必须真的映射到宿主机（`-p 6185:6185`）。

### 从 NapCat 侧验证

```bash
docker exec napcat curl -m 5 -o /dev/null -w '%{http_code}\n' http://172.22.0.2:6185/api/file/test
```

| 返回 | 含义 | 怎么办 |
| --- | --- | --- |
| `404` | ✅ 通了（令牌是假的，所以 404 正确） | 查 QQ 侧 |
| `401` | 端口通但被鉴权拦 | 改用「文件回链地址」+ 内网 IP |
| `Connection refused` | 端口没开或地址错 | 检查 IP、检查端口映射 |
| `Could not resolve host` | 容器名解析不了 | 改用 IP |
| 超时 | 被防火墙拦 | 放行 6185（仅内网） |

### 兜底机制

令牌服务不可用时（如改了面板鉴权），插件会退回旧的独立文件服务，日志会写明：

```
[fanqie] 令牌回链不可用，退回自带文件服务 http://172.22.0.2:28900（若收不到文件，请配置 file_url_base）
```

**看到这条就说明在用旧机制**，此时才需要端口映射（`-p 18999:18999`）。

### 安全提醒

- 新版走一次性令牌，不暴露目录，比旧版 `/f/<文件名>` 安全得多
- 旧兜底服务暴露整个 `downloads/` 目录，**别映射到公网**
- 面板 6185 有密码保护，但仍建议只在容器网络/内网可达

## 遇到问题怎么办

### 问题：发链接没反应

**按顺序查：**

1. **机器人本身是否正常** — 发个 `/番茄 健康` 试试
   - 回「后端在线」→ 插件没问题，是链接格式问题
   - 回「后端尚未就绪」→ 等一会儿，或看下面「后端启动失败」
   - 完全没回复 → 机器人掉线了，跟本插件无关

2. **链接格式对不对** — 必须是番茄的分享链接或纯数字书号

3. **是不是被管理员限制** — 检查「仅管理员可用」是否开着

### 问题：提示「后端尚未就绪」或「后端启动失败」

首次安装时，插件要下载一个约 10MB 的后端程序。可能遇到：

| 情况 | 解决 |
| --- | --- |
| 网络慢还在下 | 等几分钟，再发 `/番茄 健康` |
| 三个镜像都失败 | 看日志 `[fanqie] 镜像失败`，通常是网络问题 |
| 想手动放 | 见下方「手动准备后端」 |

**手动准备后端：**

1. 去 [Releases](https://github.com/zhongbai2333/Tomato-Novel-Downloader/releases) 下载对应平台的二进制
2. 重命名成 `tomato`（Windows 用 `tomato.exe`）
3. 放到：

```
AstrBot/data/plugin_data/astrbot_plugin_fanqie_novel/bin/tomato
```

4. 给执行权限（Linux/macOS）：

```bash
chmod +x AstrBot/data/plugin_data/astrbot_plugin_fanqie_novel/bin/tomato
```

5. 重启 AstrBot

### 问题：显示「完成，正在发送…」但收不到文件

**v1.3.0 已针对根因修复**（不再自开端口，改用面板端口的令牌服务）。
若仍遇到，先发一次自检指令：

```
/番茄 回链
```

- 有「可用」→ 网络通，往下看原因 A
- 全「不可用」→ 按「[端口与网络](#端口与网络)」手填「文件回链地址」

**原因 A：QQ 上传超时**

日志里出现 `rich media transfer failed` 就是这个。
需要调大 NapCat 的上传超时，编辑 NapCat 的 `onebot11_<QQ号>.json`：

```json
{
  "timeout": {
    "baseTimeout": 60000,
    "uploadSpeedKBps": 4096,
    "downloadSpeedKBps": 4096
  }
}
```

改完重启 NapCat：`docker restart napcat`

**原因 B：文件太大**

4.6MB 通常没问题。如果书特别长（比如 1000 章以上），
可以把「单文件发送上限」调小，插件就不会硬发。

### 问题：进度一直卡在某个百分比

番茄那边限流了。表现是插件还在轮询，但后端抓不动。

- 等一会儿（番茄限流通常几分钟恢复）
- 或者 `/番茄 取消`，过段时间再来
- **别连续快速重试**，会加重限流

### 问题：日志里 `[fanqie] 重启失败`

后端程序连续崩溃 3 次，插件已放弃。

```bash
# 看后端自己的日志找原因
cat AstrBot/data/plugin_data/astrbot_plugin_fanqie_novel/backend/backend.out
```

常见原因是系统 glibc 版本太老。可以换 musl 版本的后端试试。

## 常见问题 FAQ

**Q：需要番茄账号吗？要开 SVIP 吗？**

不需要。番茄正文本身是免费的，插件也不需要你登录。

**Q：会封号吗？**

插件不碰你的账号，因为它根本不登录。
但如果你**高频疯狂抓取**，服务器 IP 可能被番茄限流（表现为抓不动），换个时间就好。

**Q：抓下来的内容是完整的吗？**

是。实测 506 章，最短章节 4212 字符，平均 12957 字符，**没有一章是残缺的**。

> 网上有说法「番茄只给看 180 字」，那是**网页端未登录**的限制。
> 本插件走的是另一个通道，不受这个限制。

**Q：下载要多久？**

实测 506 章约 **40 秒到 1 分钟**。
章节多、网络差会久一些，默认超时给到 40 分钟很充裕。

**Q：能下载完本吗？还是只能下免费部分？**

番茄的书整体免费，插件抓的就是全书。
如果某本书确实有付费章节，那些章节抓不到，插件会明确报错而不是塞假内容。

**Q：生成的 TXT 在哪？**

插件下载目录：

```
AstrBot/data/plugin_data/astrbot_plugin_fanqie_novel/downloads/
```

后端自己也有个 library 目录存原件：

```
AstrBot/data/plugin_data/astrbot_plugin_fanqie_novel/library/
```

**Q：能下 EPUB 吗？**

后端支持，但本插件目前固定输出 TXT（大多数 QQ 客户端预览 TXT 更省事）。

**Q：占多少硬盘？**

后端程序约 10MB。每本书的 TXT 约 4~6MB，缓存目录里还有一份章节缓存约 20MB/本。
嫌占地方可以定期清理 `backend/` 下的书号目录。

**Q：支持多本书同时下吗？**

不支持，故意的。番茄反爬严格，并发只会让全失败。

**Q：取消后后端还在跑吗？**

是的，`/番茄 取消` 只停插件的等待，后端任务会自己跑完。
这是已知限制（见下）。

## 它是怎么工作的

给想了解原理的人（普通用户可以跳过）。

```
QQ 群
  ↓ 发链接
AstrBot 插件（就是本插件）
  ↓ HTTP
本地下载器后端（Rust 程序，插件自动管理）
  ↓
番茄小说
```

为什么要拆成两层？

因为番茄的接口有字体混淆、签名校验、反爬限流，这些很复杂且**经常变**。
把抓取交给专门的后端程序，上游一变只需要换后端，插件本身不用动。

### 几个细节

- 后端只监听 `127.0.0.1`，不对外，所以不需要密码
- 端口从 18423 起自动找空的，不会冲突
- 第一次运行会把输出格式固定成 TXT，保存目录固定到插件自己的目录
- 后端崩了会自动重启，最多 3 次
- 插件卸载/停用时会把后端和临时文件服务一起关掉，不留残留进程

### 文件是怎么发出去的

这里有个容易被忽略的坑：**NapCat 和 AstrBot 通常不在同一个容器里**，
NapCat 看不到 AstrBot 的文件。直接传路径会报：

```
ENOENT: no such file or directory
```

**v1.3.0 起**，插件把文件登记到 AstrBot 内置的令牌服务，再把带一次性令牌的 URL 交给 NapCat：

```
File(name="书名.txt", url="http://<AstrBot地址>:6185/api/file/<一次性令牌>")
```

NapCat 取一次，令牌随即失效。全程复用面板端口，不额外监听任何端口。

> v1.2.x 及更早是自己起 aiohttp 暴露 `/f/<文件名>`，依赖 NapCat 能直连该临时端口
> —— 这正是「收不到文件」的根因，现已废弃（仅保留为兜底）。

## 已知限制

1. **取消是「软取消」** — `/番茄 取消` 只停插件等待，后端任务仍会跑完
2. **首次启动慢** — 需要下载约 10MB 后端程序
3. **依赖上游项目** — 抓取能力来自 [Tomato-Novel-Downloader](https://github.com/zhongbai2333/Tomato-Novel-Downloader)，如果它长期停更、番茄又改了接口，可能需要等作者更新
4. **并发限制** — 一次只下一本，这是有意设计
