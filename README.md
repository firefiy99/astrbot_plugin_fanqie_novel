# 番茄小说下载助手

群里发一条番茄小说分享链接，插件自动抓取整本书并导出 TXT 发回聊天。

创作者：小星萤

## 特点

- **装完即用**：插件自带下载器后端，首次运行自动准备，不需要手动安装任何东西
- **整本抓取**：实测 506 章全部完整（平均每章近 13000 字符，无截断）
- **后台执行**：先回执再推文件，不会卡住 QQ 消息
- **串行队列**：番茄反爬严格，并发只会让整本失败，所以强制串行
- **节点播报**：只在 25%/50%/75% 报一次，且需已跑满 1 分钟才播，快速完成不打扰
- **结果缓存**：同一本书短期内重复请求直接重发，不重复抓取
- **失败可读**：区分「后端准备中 / 离线 / 已有任务 / 超时」四类

## 指令

```
/番茄 <分享链接>    下载整本为 TXT
/番茄 状态          查看当前任务
/番茄 取消          取消排队任务
/番茄 健康          检查后端状态
```

也可以直接把链接发到群里。行为由 `auto_download` 决定：

- `false`（默认）：先回「识别到番茄链接 xxx」，需发 `/番茄 xxx` 确认
- `true`：贴链接直接开始下载

支持的链接形态：

- `https://changdunovel.com/t/XXXXXXXX/`（短链，后端跟随跳转）
- `https://fanqienovel.com/page/<book_id>`
- `https://changdunovel.com/ug/pages/book-share?...&book_id=<id>`
- 纯数字 `book_id`

## 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `backend_mode` | `auto` | auto=自动准备并管理后端；external=连你已有的后端 |
| `backend_url` | `http://127.0.0.1:18423` | 仅 external 模式 |
| `backend_password` | 空 | 仅 external 模式 |
| `timeout_minutes` | 40 | 单本超时 |
| `poll_interval` | 20 | 轮询间隔（秒），过小易触发风控 |
| `max_queue` | 3 | 队列上限，防刷 |
| `auto_download` | `false` | 贴链接是否直接下载 |
| `progress_broadcast` | `true` | 节点播报 |
| `cache_hours` | 24 | 缓存时长，0 关闭 |
| `admin_only` | `false` | 仅白名单可用 |
| `admin_list` | 空 | 白名单 QQ |
| `max_file_mb` | 80 | 单文件发送上限 |
| `file_http_port` | 18999 | 文件转发端口，占用时自动往后找 |

## 工作方式

```
QQ 群 → 插件 → 本地后端(127.0.0.1:自动端口) → 番茄
              ← 进度 / 文件 ←
```

插件本身不直接抓番茄，抓取交给后端进程。好处是上游接口变化时
只需替换后端二进制，插件代码不用动。

后端的一些细节：

- 只监听 `127.0.0.1`，不暴露公网，因此不需要密码
- 端口从 18423 起自动探测空闲，冲突自动避让
- 首次运行把 `config.yml` 的 `novel_format` 固定为 `txt`，并把 `save_path` 固定到插件自己的 `library/` 目录
- 进程异常退出会自动重启（最多 3 次）
- 插件停用/卸载时干净退出，不留孤儿进程
- 若 `bin/` 下已有二进制则直接使用，不重复下载

### 文件是怎么发出去的（重要）

NapCat 与 AstrBot 通常跑在**不同容器**里，NapCat 看不到 AstrBot 的文件系统。
实测直接传本地路径会报：

```
ENOENT: no such file or directory, open '/AstrBot/data/plugin_data/.../xxx.txt'
```

因此插件会起一个**只服务下载目录的临时 HTTP 服务**，把文件通过 URL 交给 NapCat：

```
File(name="书名.txt", url="http://<本机内网IP>:<port>/f/书名.txt")
```

该服务仅暴露 `downloads/` 下的文件，且随插件停用而关闭。

## 关于完整性

番茄正文本身免费。网页端对未登录请求只返回约 180 字/章的预览，
但这不代表内容受限——后端走的是完整通道。实测同一本书：

```
章节数: 506
最短: 4212 字符   最长: 24022 字符
平均: 12957 字符  总 655 万字
少于 1000 字符的章节: 0
```

## 已知限制

- **QQ 文件大小**：单个 TXT 常见 4~6MB，正常可发；若 NapCat 上传超时
  （`rich media transfer failed`），需调大 NapCat 的 `timeout.baseTimeout` 与 `uploadSpeedKBps`
- **取消是软取消**：`/番茄 取消` 只停本地轮询，后端任务仍会跑完
- **首次启动较慢**：需下载约 10MB 后端二进制，期间发链接会提示「后端准备中」

## 更新日志

### v1.0.3

- **修复**：进度的 `saved_chapters` 为 0 时被 `or` 判为假值，导致误取 `group_done`，刚开始就显示 100%。改用显式判空取值
- **修复**：任务在拉文件/发文件失败时仍标记为 done，造成「显示成功但没收到文件」。现在只有真正发送成功才标 done
- **修复**：`_jobs` 字典只增不减导致内存增长，增加终态任务 2 小时自动清理
- **修复**：插件停用时未关闭临时 HTTP 服务，热重载会累积端口占用
- **修复**：`auto` 与 `cmd` 可能对同一条消息双触发。因框架会去掉指令前缀斜杠，增加中文/英文前缀判断
- **优化**：进度播报改为一次轮询只发最新一档，且需已跑满 1 分钟

### v1.0.2

- **修复**：发文件改为 HTTP URL 方式（NapCat 跨容器无法读取本地路径）
- **修复**：`save_path` 为空导致文件散落到容器工作目录，现固定到 `library/`
- **新增**：`file_http_port` 配置，端口占用自动往后探测

### v1.0.1

- **修复**：`asyncio.subprocess.DEV` 不存在导致后端启动失败
- **修复**：`/api/library` 接口不可靠（`scanned` 恒为 0），改为按书名直接走 `/download/<文件名>`

### v1.0.0

- 首个版本：分享链接解析、串行队列、节点播报、结果缓存、自动管理后端
